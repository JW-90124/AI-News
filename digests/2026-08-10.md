## 2. @ai-sdk/openai-compatible@3.0.28

- **事实**：Vercel AI SDK 发布 @ai-sdk/openai-compatible@3.0.28，修复当 provider 报告的 completion_tokens_details.reasoning_tokens 大于 completion_tokens 时（Baseten 服务推理模型在长度停止中途触发），将 outputTokens.text 钳制为 0。文本部分不会为负，total 和 reasoning 保持 provider 报告值。@ai-sdk/huggingface@2.0.28、@ai-sdk/deepinfra@3.0.28、@ai-sdk/cerebras@3.0.28 同步更新依赖。
- **技术视角**：该修复针对推理模型在长度停止时 reasoning_tokens 超过 completion_tokens 的边界情况，通过钳制文本 token 为 0 保证计数一致性，可能影响依赖 token 计数的下游逻辑。
- **行业影响**：推理模型（如 Baseten 服务的模型）在停止条件触发时可能产生不一致的 token 计数，暴露了 provider 兼容层的健壮性问题，推动 SDK 层进行防御性修复。
- **值得关注**：后续可观察其他 provider 是否出现类似计数问题，以及 SDK 是否引入更通用的 token 计数校验机制。
- 证据：[@ai-sdk/openai-compatible@3.0.28](https://github.com/vercel/ai/releases/tag/%40ai-sdk%2Fopenai-compatible%403.0.28)
- 证据：[@ai-sdk/huggingface@2.0.28](https://github.com/vercel/ai/releases/tag/%40ai-sdk%2Fhuggingface%402.0.28)
- 证据：[@ai-sdk/deepinfra@3.0.28](https://github.com/vercel/ai/releases/tag/%40ai-sdk%2Fdeepinfra%403.0.28)
- 证据：[@ai-sdk/cerebras@3.0.28](https://github.com/vercel/ai/releases/tag/%40ai-sdk%2Fcerebras%403.0.28)
