## 5. b11223

- **事实**：llama.cpp 发布 b11223，允许对因果 LLM 重排序器（如 Qwen3、Qwen3-VL）的 RANK pooling 输入进行批拆分。此前服务器拒绝所有大于 n_ubatch 的 RANK-pooling 输入，且图构建器硬编码 QWEN3/QWEN3VL 架构检查来判断 last-token pooling，导致因果模型的长文档与多模态重排序失效。修复方式为暴露 llama_get_causal_attn(ctx) 以查询运行时有效注意力类型，并暴露 llama_model_is_causal(model) 以从 GGUF 元数据查询静态架构属性；can_split() 现在在上下文为因果时允许 RANK pooling 的分块预填充，图构建器的内联架构检查被替换为同一 cparams.causal_attn 谓词。
- **技术视角**：该改动将重排序器的批处理能力从架构硬编码判断转为基于运行时有效注意力类型的判断，可能改善因果 LLM 重排序器在长输入与多模态场景下的可用性。可验证下一信号：后续版本是否出现针对 RANK pooling 分块预填充的性能基准或回归测试。
- **行业影响**：这属于开源推理栈对重排序模型支持方式的调整，反映因果 LLM 被复用为重排序器的趋势正在被工具链接纳。可验证下一信号：其他推理框架或服务端是否跟进类似的因果重排序器分块预填充支持。
- **值得关注**：若该改动被广泛采用，因果 LLM 重排序器在长文档与多模态检索场景中的部署门槛可能降低。可验证下一信号：llama.cpp 后续发布说明中是否继续扩展 RANK pooling 相关能力或修复。
