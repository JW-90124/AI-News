## 1. b11576: graph: pad the KV dimension of the no-cache attention to 256 (#30416)

- **事实**：llama.cpp 发布 b11576 版本，针对 no-cache attention 路径做修复：该路径构建 [n_tokens, n_tokens] 掩码并传入未填充的 K 和 V，使 FLASH_ATTN_EXT 看到 K->ne[1] == n_tokens；head size 512 的 CUDA kernel 要求长度为 FATTN_KQ_STRIDE 的倍数，因此多数长度下该算子回退到 CPU，且 -fa auto 探测（1 token）会对此类模型禁用 flash attention。修复方式是按 llama_kv_cache::get_n_kv 的方式填充掩码，并用零将 K 和 V 填充到掩码的 KV 维度；clef 自行构建因果掩码并做同样填充。
- **技术视角**：该修复指向一个具体约束：head size 512 的 CUDA flash attention kernel 要求 KV 维度为 FATTN_KQ_STRIDE 的倍数，未填充输入会触发 CPU 回退，并可能让 -fa auto 的 1 token 探测误判为禁用 flash attention。可验证的下一信号是后续版本中该路径是否不再出现 CPU 回退，以及 -fa auto 探测是否对 head size 512 模型给出启用结果。
- **行业影响**：这是开源推理栈在长上下文/大 head size 场景下的工程修补，反映 flash attention 内核的维度对齐要求会直接影响算子后端选择与性能表现；其影响范围限于使用该路径与相关 head size 的模型。
- **值得关注**：若该填充逻辑被合并并稳定，相关模型在 no-cache 路径下应能走 CUDA flash attention 而非 CPU 回退；可观察后续 release note 或 issue 中是否报告回退消失与 -fa auto 行为变化。
- 证据：[b11576: graph: pad the KV dimension of the no-cache attention to 256 (#30416)](https://github.com/ggml-org/llama.cpp/releases/tag/b11576)
