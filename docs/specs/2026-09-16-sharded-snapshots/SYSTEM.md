# 仓库快照分片

## 问题与契约

每日刷新生成的 v1.json 已超过 GitHub 单文件 100 MiB 上限，push 被拒绝，采集结果无法持久化。保留全部历史、schemaVersion 1 和原有合并规则；不删除历史、不引入 LFS 或额外服务。

超过 8 MiB 的快照使用 v1.json 清单及 v1.json.parts/ 下的 JSON 数组分片，每片最多 8 MiB（UTF-8 字节数）。小快照继续使用原有 JSON 对象。清单包含独立存储格式标识、表名、片名、SHA-256 和记录数；读取时完整校验后才启动数据库恢复事务。旧单文件快照仍可恢复。

分片用内容哈希命名，先原子写片再原子替换清单，最后清理旧片；写入失败前的清单保持可用。单条记录超限时明确失败，不丢弃或截断数据。所有数据继续经过既有隐私校验，并保留文本 Git diff。

## 工作流与迁移

远端合并改为 git archive 提取整个 data/snapshot 目录到临时目录。刷新、审计的隐私扫描及 git add 覆盖整个快照目录；Pages 监听全部快照文件。先发布兼容读写实现；下一次快照写入自动转换存储，不修改事实、排名或来源策略。

## 验证与回滚

覆盖旧格式、分片往返、UTF-8 大小、确定性、缺片、校验和损坏、路径越界、超大单条记录及旧片清理；运行已有数据库快照恢复测试和 npm run check/build。使用真实仓库快照验证无损迁移。云端仍须确认刷新、审计和 Pages 成功。

回滚必须连同 data/snapshot 一起恢复到旧代码兼容的提交；不得只回滚读写代码并保留清单格式。大快照不得重新合并成超过 GitHub 上限的单文件提交。
